# רשימת קניות משותפת — מסמך עיצוב

**תאריך:** 2026-10-09
**סטטוס:** ממתין לאישור

## 1. מטרה

אפליקציית רשימת קניות משותפת לזוג (שני משתמשים, שניהם עם אייפון).
העיקרון המנחה: **הוספה קלילה ומהירה**, עם מועדפים (⭐) ופריטים אחרונים (🕘), ועיצוב יפה לעין.

**הצלחה נראית כך:** אחד מוסיף פריט בבית בכמה שניות, השני רואה אותו מיד בסופר, מסמן מה נכנס לעגלה — וגם בלי קליטה זה עובד.

## 3. מסכים והתנהגות

### 3.1 כניסה
- פעם ראשונה: כפתור "התחבר עם Google". אחרי זה ההתחברות נשמרת.
- מייל שאינו ברשימת המורשים מקבל מסך "אין לך גישה לרשימה הזו" + כפתור התנתקות. שום מידע לא נחשף.

### 3.2 לשונית 📝 רשימה (מסך ראשי)
- כותרת "הרשימה שלנו" + שורת סטטוס: "N פריטים · עודכן ע"י [שם פרטי מחשבון Google] לפני X".
- פריטים פעילים מקובצים לפי מחלקה, בסדר מחלקות קבוע (סדר הליכה טיפוסי בסופר, ראו 5.3). מחלקות ריקות לא מוצגות.
- כל פריט מציג: עיגול סימון, שם, הערה (אפור קטן מתחת לשם, אם קיימת), ותג כמות `×N`.
- **לחיצה** על פריט: מעבירה ל"בעגלה" / מחזירה ממנה.
- **החלקה הצידה** חושפת: 🗑 מחק · 📂 העבר מחלקה · ⭐ הוסף/הסר ממועדפים.
  - "העבר מחלקה" פותח בוחר מחלקות; הבחירה נשמרת ל-`catalog` ומשפיעה על כל הוספה עתידית של אותו מוצר.
  - אחרי מחיקה: הודעת "נמחק · בטל" ל-4 שניות.
- אזור **"בעגלה (N)"** בתחתית הרשימה, עם הפריטים המסומנים (מעומעמים, קו חוצה).
- כשיש לפחות פריט אחד בעגלה — כפתור **"סיימתי קנייה"**.
- מצב ריק: איור/טקסט ידידותי "הרשימה ריקה — לחצו + כדי להוסיף".

### 3.3 חלון ההוספה (כפתור +)
- חלון שעולה מלמטה (bottom sheet), המקלדת נפתחת אוטומטית.
- שורה אחת: שדה שם · כפתורי −/+ לכמות (מתחיל ב-1, מינימום 1) · כפתור 📝 שפותח שדה הערה.
- **לפני הקלדה:** צ'יפים של מועדפים ושל אחרונים (עד 8 מכל סוג). לחיצה על צ'יפ מוסיפה את הפריט בכמות 1 לרשימה (החלון נשאר פתוח).
- **תוך כדי הקלדה:** רשימת הצעות מתוך `catalog` (מועדפים קודם, אחר כך לפי `lastBoughtAt`), התאמה לפי תחילית/תת-מחרוזת של השם המנורמל. ההצעה האחרונה תמיד: "➕ הוסף '[הטקסט]'".
- **Enter / לחיצה על הצעה:** מוסיף את הפריט, מאפס את השדה, הכמות חוזרת ל-1 וההערה מתרוקנת; החלון נשאר פתוח להוספה הבאה.
- סגירה: החלקה למטה או לחיצה מחוץ לחלון.
- **פריט שכבר קיים ברשימה הפעילה** (לפי שם מנורמל, ולא בעגלה): לא נוצרת שורה כפולה — הכמות החדשה **מתווספת** לכמות הקיימת, וההערה מתעדכנת אם הוזנה. פריט זהה שנמצא ב"בעגלה" — מוחזר לרשימה הפעילה עם הכמות החדשה.

### 3.4 לשונית ⭐ מועדפים
- כל רשומות `catalog` עם `isFavorite = true`, ממוינות לפי שם.
- לחיצה על פריט: מוסיף לרשימה (כמות 1, לפי כלל הכפילויות שב-3.3) ומציג אישור קצר.
- לחיצה על ⭐: מסיר ממועדפים.
- פריט שכבר ברשימה הפעילה מסומן ויזואלית ("ברשימה ✓").

### 3.5 לשונית 🕘 אחרונים
- רשומות `catalog` עם `lastBoughtAt`, ממוינות מהחדש לישן, עד 50.
- לחיצה: מוסיף לרשימה (כמו במועדפים). לחיצה על ☆: מוסיף/מסיר ממועדפים.
- פריט שכבר ברשימה הפעילה מסומן "ברשימה ✓".

### 3.6 "סיימתי קנייה"
- כל הפריטים ב"בעגלה" נמחקים מ-`items`; לכל אחד מתעדכן ב-`catalog`: `lastBoughtAt = now`.
- פעולה אטומית (batch write).
- מקרה טעות מכוסה: הכל זמין ב"אחרונים" להחזרה בלחיצה.

### 3.7 מחוץ לתחום (גרסה 1)
ריבוי רשימות, מחירים/תקציב, התראות push, משתמשים נוספים מעבר לשניים, סריקת ברקוד, עריכת כמות של פריט שכבר ברשימה (אפשר למחוק ולהוסיף, או להוסיף שוב — הכמות מצטברת).

## 4. ארכיטקטורה

```
אייפון (PWA, React)
   ├── Firebase Auth  ← התחברות Google (redirect, דרך הדומיין שלנו)
   └── Firestore      ← נתונים + סנכרון חי + מטמון מקומי (offline)
Vercel ← מארח את הקבצים הסטטיים + rewrite של /__/auth/* ל-Firebase
```

### 4.1 Stack
- React + TypeScript + Vite
- `vite-plugin-pwa` (manifest, service worker, אייקונים, `display: standalone`)
- Firebase JS SDK v10+ עם `persistentLocalCache` (Firestore offline)
- Vitest לבדיקות יחידה; Firebase Emulator לבדיקת חוקי אבטחה

### 4.2 מבנה קוד
```
src/
  categorize/   מילון מחלקות, נרמול שמות, parse — פונקציות טהורות, ללא Firebase
  data/         שכבה מעל Firestore: listen/add/toggleCart/remove/finishShopping/setFavorite/setDept
  auth/         התחברות, בדיקת הרשאה, מסך "אין גישה"
  ui/           Tabs, ListTab, FavoritesTab, RecentTab, AddSheet, SwipeRow, DeptPicker, UndoToast, OfflineBanner
  theme/        טוקני עיצוב (צבעים, רדיוסים, צלליות) של "פסטל רך"
```
כל יחידה ניתנת להבנה ולבדיקה בנפרד; `ui/` לא ניגש ל-Firestore ישירות אלא דרך `data/`.

### 4.3 התחברות ב-PWA באייפון
התחברות Google בתוך PWA שמותקן למסך הבית באייפון נכשלת בתצורה ברירת המחדל (חסימת אחסון צד-שלישי ב-Safari). הפתרון:
- `authDomain` של Firebase מוגדר לדומיין של האפליקציה ב-Vercel.
- ב-`vercel.json`: rewrite של `/__/auth/:path*` אל `https://<project-id>.firebaseapp.com/__/auth/:path*`.
- שימוש ב-`signInWithRedirect`.
- כתובת ה-redirect מתווספת ל-Authorized domains ב-Firebase ול-OAuth client ב-Google Cloud.

## 5. מודל נתונים (Firestore)

מסמך בית יחיד: `households/main`.

### 5.1 `households/main/items/{itemId}` — הרשימה הנוכחית
| שדה | סוג | הערה |
|---|---|---|
| `name` | string | כפי שהוקלד |
| `key` | string | שם מנורמל (ראו 5.4) |
| `qty` | number | ≥ 1 |
| `note` | string | יכול להיות ריק |
| `dept` | string | מזהה מחלקה |
| `inCart` | boolean | |
| `createdAt` / `updatedAt` | timestamp | |
| `updatedBy` | string | שם פרטי מחשבון Google |

### 5.2 `households/main/catalog/{key}` — הזיכרון
| שדה | סוג | הערה |
|---|---|---|
| `name` | string | התצוגה האחרונה שהוקלדה |
| `dept` | string \| null | מחלקה שנלמדה מהמשתמשים; `null` = להשתמש במילון |
| `isFavorite` | boolean | |
| `lastBoughtAt` | timestamp \| null | |

רשומת `catalog` נוצרת (אם לא קיימת) בכל הוספה של פריט.

### 5.3 מחלקות (סדר תצוגה קבוע)
ירקות ופירות 🥬 · מאפים ולחם 🥖 · חלבי וביצים 🧀 · בשר ועוף 🍗 · דגים 🐟 · מזון יבש ושימורים 🥫 · תבלינים ורטבים 🧂 · חטיפים ומתוקים 🍫 · משקאות 🥤 · קפואים 🧊 · ניקיון 🧴 · טואלטיקה והיגיינה 🧻 · תינוקות 🍼 · שונות 📦

### 5.4 שיוך מחלקה ונרמול
- **נרמול (`key`):** הסרת רווחים כפולים וניקוד, אחידות כתיב מלא/חסר נפוצה (י/יי, ו/וו), והורדת סיומות ריבוי נפוצות (ים/ות) לצורך התאמה במילון.
- **סדר עדיפות לשיוך:** `catalog[key].dept` (נלמד) ← התאמה מדויקת במילון ← התאמה לפי מילה ראשונה במילון (למשל "גבינה צהובה" → "גבינה") ← "שונות".
- **המילון:** קובץ TypeScript סטטי עם כמה מאות מוצרים נפוצים בעברית ממופים למחלקות.

## 6. אבטחה

חוקי Firestore:
- גישת קריאה/כתיבה ל-`households/main/**` רק אם `request.auth != null`, `request.auth.token.email_verified == true`, ו-`request.auth.token.email` נמצא ברשימת שתי הכתובות המורשות (מוגדרת בחוקים עצמם).
- ולידציה בסיסית בכתיבה ל-`items`: `qty` מספר שלם ≥ 1, `name` מחרוזת לא ריקה עד 60 תווים, `note` עד 120 תווים.
- כל שאר הנתיבים חסומים.

שתי כתובות ה-Gmail יימסרו ע"י המשתמש לפני תחילת המימוש ויוזנו לחוקים ולקונפיגורציה.

## 9. בדיקות
- **יחידה (Vitest):** נרמול שמות, שיוך מחלקה (כולל יחיד/רבים ועדיפות `catalog` על המילון), כלל איחוד כפילויות בהוספה, מיון והגבלת "אחרונים", סדר הצעות בהשלמה האוטומטית.
- **חוקי אבטחה (Firebase Emulator):** מייל מורשה — מותר; מייל זר — חסום; לא מחובר — חסום; ולידציית שדות.
- **ידני, על שני אייפונים:** התקנה למסך הבית, התחברות, סנכרון חי בין המכשירים, מצב טיסה וחזרה, "סיימתי קנייה", החלקה ובטל.

## 10. הקמה — מה המשתמש עושה בעצמו
1. יצירת פרויקט Firebase בחשבון Google שלו, הפעלת Authentication (ספק Google) ו-Firestore (הדרכה צעד-אחר-צעד תינתן).
2. מסירת שתי כתובות ה-Gmail המורשות.
3. חיבור הריפו ל-Vercel והגדרת משתני הסביבה של Firebase.
